Interactivité

Événements, conditions, listes et formulaires

Objectifs

  • Réagir aux actions de l'utilisateur sans déclencher de boucle infinie.
  • Afficher un élément ou un autre selon une condition.
  • Afficher une liste et comprendre à quoi sert la key.
  • Écrire un formulaire « contrôlé » et comprendre son cycle.

Les événements

Un événement, c'est une action de l'utilisateur que le navigateur détecte : un clic, une frappe au clavier, un envoi de formulaire. Voici ce qui se passe quand l'utilisateur clique sur un bouton React :

  1. Le navigateur détecte le clicsur le bouton, dans le DOM.
  2. React appelle ta fonctioncelle que tu as donnée à onClick, avec un objet qui décrit l'événement.
  3. Ta fonction agiten général, elle appelle un setter : nouvel état, nouveau rendu.

Ce que tu utiliseras le plus souvent dans l'objet événement :

Propriété ou méthodeCe qu'elle donneExemple d'usage
e.targetl'élément du DOM concernésavoir quel champ a changé
e.target.valuele texte d'un champ de saisie ou d'un selectsetEmail(e.target.value)

e.keyla touche pressée (événements clavier)if (e.key === "Enter") …

Les événements les plus courants : onClick, onChange (un champ change), onSubmit (un formulaire est envoyé), onKeyDown (une touche), onFocus et onBlur (un champ gagne ou perd le focus).

C'est l'erreur la plus fréquente des débutants :

Analogie

onClick={openModal}, c'est laisser ton numéro de téléphone au bouton : « appelle-moi quand on te clique ». onClick={openModal()}, c'est composer le numéro tout de suite, au moment où la page s'affiche, et donner au bouton le résultat de l'appel.

Quand la fonction a besoin d'un argument, on écrit un petit mot à transmettre : () => remove(42) veut dire « au clic, appelle remove avec 42 ».

Si la fonction appelée trop tôt modifie l'état (onClick={setOpen(true)}), c'est la boucle infinie : l'affichage appelle le setter, qui demande un nouvel affichage, qui rappelle le setter… React s'arrête avec l'erreur Too many re-renders.

Afficher sous condition

Il y a quatre façons d'afficher quelque chose « seulement si », toutes en JavaScript ordinaire :

Pour &&, souviens-toi du module 01 : a && b vaut b si a est vrai, et a sinon. Et du module 03 : React n'affiche rien pour false, null et undefined, mais il affiche les nombres. Joue avec les conditions :

if (isLoading) return <Spinner />;

return (
  <div>
    {tasks.length === 0 ? <EmptyState /> : <TaskList />}
    {tasks.length > 0 && <p>{tasks.length} tâches</p>}
    {tasks.length && <p>Version piégée</p>}

Piège

Ligne 7 de la démo : avec une liste vide, {tasks.length && …} affiche un 0 à l'écran. 0 && … vaut 0, et React affiche les nombres. Écris toujours une vraie condition booléenne : tasks.length > 0 &&.

Afficher une liste

Pour afficher une liste, on transforme le tableau de données en tableau de JSX avec map. React sait afficher un tableau d'éléments (module 03, règle 3).

Donnée→ ce que map produit

À quoi sert la key ?

Quand la liste change (un ajout, une suppression, un tri), React compare l'ancienne et la nouvelle liste (module 00, étape 3). Il doit savoir quelle ligne est quelle ligne d'un affichage à l'autre, pour déplacer, garder ou supprimer les bons éléments du DOM. La key est l'identité de chaque élément.

Analogie

Les coureurs d'un marathon portent un dossard. Quand ils changent de position, on les reconnaît grâce à leur numéro, pas grâce à leur place dans le peloton. Utiliser l'index comme key, c'est identifier les coureurs par leur position : dès que le premier abandonne, tout le monde change d'identité.

Chaque ligne ci-dessous contient un champ de note. Ces notes ne sont pas dans les données : elles vivent dans le champ lui-même, comme un texte en cours de saisie. Supprime la première tâche dans les deux modes :

Démo · l'index comme key

    Avant de supprimer, regarde quelle note accompagne chaque tâche.

    Avec key={index}, après la suppression, React voit : « la ligne 0 existe toujours, la ligne 1 aussi, la ligne 2 a disparu ». Il garde donc les deux premières lignes du DOM (avec leurs notes), change seulement leurs titres, et supprime la dernière. Les notes ont glissé d'une tâche à l'autre. Avec key={task.id}, React sait que c'est la tâche a qui a disparu, et retire exactement sa ligne.

    Côté backend

    La key est la clé primaire de la ligne. Synchroniser deux listes sur leur position plutôt que sur leur identifiant donne le même genre de catastrophe qu'une mise à jour SQL faite sur le numéro de ligne.

    • Une key doit être unique parmi ses voisines et stable dans le temps : l'identifiant venu de ta base est idéal.
    • Jamais Math.random() : une nouvelle clé à chaque rendu détruit et recrée tous les éléments.
    • L'index ne convient que pour une liste qui ne sera jamais réordonnée, filtrée, ni modifiée au milieu.
    • La key se met sur l'élément renvoyé par map, pas à l'intérieur du composant.

    Astuce utile : changer la key d'un composant force React à le recréer de zéro, état compris.

    Les formulaires contrôlés

    Dans un champ « contrôlé », c'est l'état React qui décide de ce que le champ affiche. Le champ ne fait que signaler les frappes. Ce qui se passe à chaque touche :

    1. Tu tapes « a »le navigateur déclenche l'événement change du champ.
    2. onChange(e)React appelle ta fonction ; e.target.value contient le texte avec le « a ».
    3. setEmail(...)tu enregistres ce texte dans l'état, ce qui demande un rendu.
    4. Nouveau renduvalue={email} affiche le nouveau texte dans le champ.

    Tape dans le champ de la démo. Essaie ensuite les deux options : forcer les minuscules montre que c'est toi qui décides de ce qui s'affiche ; oublier onChange montre ce qui arrive quand le champ ne peut plus prévenir l'état.

    Piège

    Le message A component is changing an uncontrolled input to be controlled signifie que value valait undefined au départ (par exemple useState() sans valeur). Initialise toujours un champ texte avec "".

    Dans les vrais projets, tu croiseras aussi des bibliothèques de formulaires (react-hook-form, avec zod pour la validation) et, en React 19, <form action={fonction}> avec useActionState. Le principe ci-dessus reste la base pour les comprendre.

    En bref

    • On donne une fonction à onClick, jamais le résultat d'un appel ; pour passer un argument, on l'enveloppe : () => remove(id).
    • Conditions : if + return, ternaire, ou && avec une vraie condition booléenne (attention au 0).
    • Listes : map + une key stable et unique, l'identifiant de la donnée, jamais l'index d'une liste qui bouge.
    • Formulaire contrôlé : value lit l'état, onChange l'écrit.
