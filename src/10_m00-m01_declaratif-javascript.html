Qu'est-ce que le DOM ?

Quand tu ouvres une page web, voici ce qui se passe, dans l'ordre :

  1. Le serveur envoie un fichier HTML. Ce n'est que du texte.
  2. Le navigateur lit ce texte et construit en mémoire un arbre d'objets : un objet par balise, rangé dans son parent. Cet arbre s'appelle le DOM (Document Object Model, « le modèle objet du document »).
  3. Le navigateur dessine l'écran à partir de cet arbre. Pas à partir du texte HTML : à partir du DOM.
  4. JavaScript peut lire et modifier cet arbre. Dès qu'un objet change, le navigateur redessine la partie de l'écran concernée.

Sans React, modifier l'écran consiste donc à aller chercher un objet dans cet arbre et à le changer :

Analogie

Le HTML, c'est la notice de montage d'un meuble en kit : du papier. Le DOM, c'est le meuble une fois monté dans ton salon. L'écran, c'est ce que tu vois en entrant dans la pièce.

Une fois le meuble monté, tu ne retouches plus la notice : pour déplacer une étagère, tu agis directement sur le meuble. JavaScript fait pareil : il agit sur le DOM, et ce que tu vois change.

Côté backend

Tu connais json.loads() en Python : un texte JSON devient un dictionnaire que tu peux modifier. Le navigateur fait la même chose avec le HTML : le texte devient un arbre d'objets JavaScript, le DOM. La différence : le navigateur surveille cet arbre et redessine l'écran dès qu'il change.

Impératif ou déclaratif

Ces deux styles portent un nom :

  • Impératif : tu donnes les étapes. « Trouve le paragraphe, change son texte, puis trouve la pastille, change son chiffre… »
  • Déclaratif : tu décris le résultat. « L'en-tête affiche le nombre de tâches restantes. » L'outil se charge des étapes.

Analogie

En taxi, le style impératif consiste à guider le chauffeur rue par rue : « à gauche, tout droit, deuxième à droite ». Le style déclaratif consiste à donner l'adresse : le GPS calcule le trajet, et le recalcule si une rue est fermée.

Autre image : un tableur. La cellule =A1*2 ne contient pas d'instruction « mets-toi à jour quand A1 change ». Elle décrit un résultat, et le tableur s'occupe du reste. Tes composants React sont les formules ; les données sont les cellules d'entrée.

Analogie · les étapes 3 et 4

Pense à un décorateur d'intérieur. Tu lui montres une photo de la pièce telle que tu la veux. Il compare avec la pièce actuelle et ne bouge que ce qui diffère : il déplace la lampe, il ne vide pas toute la maison pour la remeubler. C'est le jeu des sept différences, appliqué à l'écran.

Pourquoi ne pas tout reconstruire ? Parce que modifier le DOM coûte du temps, et que tout reconstruire ferait perdre au passage le texte en cours de saisie, la position de défilement ou le champ actif.

À retenir

Tu entendras parler de « DOM virtuel ». C'est le nom donné à la description légère de l'écran que tes composants renvoient (étape 2) et que React compare (étape 3), avant de toucher au vrai DOM (étape 4).

Quelle version de React ?

Ce cours suit React 19 ; la version stable actuelle est la 19.3, publiée le 9 septembre 2026. Les fondamentaux présentés ici n'ont pas bougé depuis l'arrivée des hooks en 2019. Dans de vieux projets ou tutoriels, tu croiseras des composants écrits sous forme de classes, l'outil create-react-app (déprécié depuis février 2025) ou ReactDOM.render (supprimé en React 19). On verra comment les reconnaître.

En bref

  • Le navigateur transforme le HTML en DOM, un arbre d'objets, et dessine l'écran à partir de lui.
  • Avec React, tu ne modifies pas le DOM : tu modifies les données, tes composants décrivent l'écran, React applique les différences.
  • Comme tout part des mêmes données, plusieurs zones de l'écran ne peuvent plus se contredire.

Qu'est-ce que le DOM ?

Le HTML est du texte, lu une fois. Le DOM est l'arbre d'objets construit à partir de ce texte. Il existe avec ou sans React : React se contente de le modifier pour toi.

Dans React, une donnée change et l'écran doit suivre. Que fais-tu ?

C'est le cycle du schéma : données, description, comparaison, modification du DOM, affichage. Tu n'interviens qu'au début (les données) et dans la description (tes composants).

2. Les variables : const et let

Règle simple : écris const partout, et let seulement si tu dois réassigner la variable. Le vieux mot-clé var se comporte de façon surprenante : ignore-le. Une variable n'existe que dans le bloc { … } où elle est déclarée.

7. Vérité, égalité

Piège

  1. Un tableau vide est « vrai ». En Python, [] est faux ; en JavaScript, [] et {} sont vrais. Les seules valeurs fausses sont false, 0, "", null, undefined et NaN. Pour tester une liste, écris items.length > 0.
  2. == convertit les types : "1" == 1 est vrai. Utilise toujours ===, qui compare sans conversion.

8. Valeur ou référence : la notion la plus importante pour React

Les valeurs simples (nombres, chaînes, booléens) sont copiées. Les objets et les tableaux, eux, sont partagés : une variable ne contient pas l'objet, elle contient son adresse en mémoire.

u1 → objet n°1 u2 → objet n°1 u3 → objet n°2
objet n°1{ name: "Grace" }
objet n°2{ name: "Grace" }

Analogie

Une variable qui « contient » un objet est comme un papier où est notée l'adresse d'une maison. Copier la variable, c'est recopier l'adresse sur un deuxième papier : il y a toujours une seule maison. Si quelqu'un repeint la maison, tous les détenteurs de l'adresse la verront repeinte. Pour avoir deux maisons, il faut en construire une seconde.

=== sur deux objets compare les adresses, pas l'intérieur des maisons. React compare de cette façon : retiens cette image, le module 05 en dépend.

12. L'asynchrone : Promise, async, await

Un appel réseau prend du temps. JavaScript ne bloque pas en l'attendant : il te donne tout de suite une Promise, une promesse de résultat futur, et continue son travail.

Analogie

Au pressing, on te remet un ticket tout de suite ; les vêtements, tu les récupères plus tard. La Promise est le ticket. await veut dire « j'attends ici que le ticket soit honoré avant de continuer cette fonction ».

Côté backend

Une Promise joue le rôle d'une Task en C# ou d'une coroutine en Python, et async / await s'utilisent de la même façon. Différence importante : fetch ne lève une exception qu'en cas d'échec réseau. Un 404 ou un 500 renvoie une réponse normale ; c'est à toi de tester res.ok.
